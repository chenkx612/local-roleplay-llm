# morgana-v2 实验收尾报告

## 1. 版本结论

`morgana-v2` 于 2026-08-13 收尾。v2 走通了 Persona 与数据、Base、Teacher-corrected SFT、
主观偏好 DPO、两类 GRPO、post-GRPO DPO 和分层 Dev/holdout 评测，形成了一个可检查、可复现的
小规模后训练闭环。

v2 的核心结论不是“得到一个全面通过的最终模型”，而是明确了不同训练阶段各自能够可靠解决的
问题边界：

1. SFT 能把不可用的 Base 提升为基本稳定、可读且多数相关的角色回复，是 v2 唯一完成正式人工
   门槛的训练阶段。
2. 使用在线主观 Judge 的 GRPO 和多轮前置 DPO 都没有稳定改善角色一致性与对话质量。
3. 规则型 GRPO 能显著改善长度、动作、格式和错误自称等可量化下限，但不能据此推断主观角色
   质量同步改善。
4. post-GRPO DPO 能改善部分定向语义样本和 Reward v2，但所有 run 都至少在生成稳定性或错误
   自称上回退，没有模型通过完整自动门槛。

因此 v2 不发布“全面最优”的最终 checkpoint：

- `output/morgana-v2/stage2-sft/4/` 是人工验证最充分、适合作为稳定基线的版本。
- `output/morgana-v2/stage4-grpo/20260812-2144/` 是规则指标最强的候选，适合保留为规则型 GRPO
  方法结果；其正式人工复核未填写，不能替代 SFT 的主观质量结论。
- `output/morgana-v2/post-grpo-dpo/train/20260813-0143/` 是 post-GRPO DPO 中综合最均衡的诊断
  候选，但自动门槛失败，不晋升为最终模型。
- `20260813-0211` 只取得最高 Reward v2 均分，错误自称和退化均回退，不优于 `0143` 的综合表现。

原计划中的冻结 20 条 Eval 没有执行 Base、SFT、GRPO、post-GRPO DPO 四方统一生成与人工比较。
本文只能依据各阶段冻结的 Dev/holdout 作收尾判断，不能宣称完成了正式统一 Eval，也不能把结论
外推到其他角色、模型或采样条件。

## 2. 实验范围与运行基线

- 角色：摩尔加纳。
- 训练基座：固定 revision 的 `Qwen/Qwen3.5-2B`。
- 本地 Student/Base：`mlx-community/Qwen3.5-2B-4bit`，revision
  `674aaa7240b91e8012fcad5d791b7dfe5ba90207`。
- 训练方式：ms-swift、bitsandbytes 4-bit NF4 QLoRA、关闭 thinking。
- 主要 GPU 环境：AutoDL，早期为 RTX 3090 24GB；Stage 4 与后续 run 实际识别为
  RTX 4080 SUPER 31.48 GiB。
- 主要训练精度：模型计算、BNB compute 和 LoRA 参数均为 FP32，显式关闭 FP16/BF16。
- 固定 Dev seed：`20260807`。
- 数据目录：`data/runs/morgana-v2/`。
- 模型与运行目录：`output/morgana-v2/`。

v2 继续沿用三层质量顺序：先判断生成稳定性，再判断角色一致性，最后判断对话质量。动作括号、
emoji、固定开头、自称频率和长度主要作为诊断或规则型奖励，不允许单独替代整体质量判断。

## 3. 数据与评测资产

### 3.1 基础数据

初始数据从五类场景各生成 20 条 Prompt，共 100 条，并按固定 seed 切分：

| Split | 数量 | 每类场景 | 用途 |
|---|---:|---:|---|
| SFT | 50 | 10 | Teacher-corrected 监督训练 |
| 旧 GRPO / 后迁移 DPO | 20 | 4 | 主观偏好实验 |
| Dev | 10 | 2 | 阶段选择与诊断 |
| Eval | 20 | 4 | 冻结的最终评测集，v2 未正式执行 |

四个 split 共 100 条，规范化后全局唯一；与 v1 的 105 条历史 Prompt 也没有规范化精确重复或
高相似重复。所有正式数据在完整生成后原子发布，避免了 v1 暴露的残缺写盘和训练/评测泄漏。

SFT 最终使用 50 条 Teacher v8 标签和 12 条由 Dev bad case 驱动的定向补强，共 62 条。补强覆盖
主客体识别、事件与情绪识别、身份边界、问题意图和回答相关性。62/62 标签使用“吾辈”，且不含
“本大爷”或“本喵”。

### 3.2 偏好与规则数据

前置 DPO 先后构造过 17、30、31 和 17 对训练数据，用于验证数据规模、绝对质量门、最小偏好
分差、RPO 和最小编辑 pair。数据质量逐步提高，但没有带来稳定的 Dev 主观收益。

规则型 GRPO 使用 20 条与其他 split 隔离的规则压力 Prompt；成功 run 每题生成 8 个候选。
Reward v2 将长度、句数、动作、自称和格式处理为连续违规距离，解决了旧奖励大量并列、零方差和
主要依赖长度排序的问题。

post-GRPO DPO 另外生成 90 条训练 Prompt 和 9 条隔离 holdout：

- 原始轮 30 条 Prompt，每题 6 个候选，冻结 20 对。
- 扩充轮 60 条 Prompt，每题批量生成 8 个候选，冻结 41 对。
- 合并训练集共 61 对：背景编造 19、视角错位 19、情绪承接 23。
- Teacher chosen 共 14 对，占 22.95%；扩充轮 9 条 Teacher chosen 在首次合并训练后重新修正。

## 4. Base 与 SFT

### 4.1 Base

本地 MLX Base 在最初 10 条 Dev 上实现 10/10 非空、正常结束和首次生成成功；`max_tokens=256`
曾导致一条截断，提升到 512 后完成冻结基线。

后续同 Transformers 推理链路下的 Base 明显更差，在最终 SFT 对照中出现 9/10 退化和 1/10
乱码。这使 SFT 相对 Base 的改善可信，但也让相对胜率更容易达到；v2 没有完成统一 Eval 来充分
消除推理链路和小样本带来的不确定性。

### 4.2 SFT 技术迭代

SFT 阶段最重要的工程发现是：命令结束和 checkpoint 存在不等于训练有效。一次运行因 ms-swift
隐式启用 FP16，前 6 个 `grad_norm` 为 `NaN`；流程正确标记为 `training_failed`，未发布 adapter
或继续 Dev 推理。此后训练前后均校验实际精度、optimizer steps、梯度、LoRA-B 更新和 adapter
重载。

最终 SFT 使用 62 条数据、3 epochs、物理 batch size 2、梯度累积 2、学习率 `5e-5`：

- 48/48 optimizer steps 正常完成，耗时 185.4 秒。
- 三个 epoch 平均 loss：`2.7107 → 2.2956 → 2.1124`。
- 全部梯度有限，186/186 个 LoRA-B 张量产生非零更新。
- adapter SHA-256：`617e6e00535fa356272d32fb16d8fe8d451a9c3cfd2f766f56af02cdf2f9b78d`。

### 4.3 SFT 结果

| 指标 | 同后端 Base | 最终 SFT |
|---|---:|---:|
| 完整输出 / 正常结束 | 10/10 | 10/10 |
| 截断 | 0 | 0 |
| 退化输出 | 9/10 | 1/10 |
| 乱码 | 1/10 | 0/10 |
| 错误自称 | 10/10 | 1/10 |
| 标志性“吾辈” | 0/10 | 0/10 |

匿名人工复核中，SFT 胜 10/10、明显落后 0/10、无阻断性严重问题。Base/SFT 的生成稳定性、
角色一致性和对话质量均分分别为 `3.3/8.0`、`1.4/5.2`、`1.5/5.7`。

SFT 完成了从“不可用”到“基本可用”的提升，但绝对角色一致性只有 5.2。训练标签中的“吾辈”
没有迁移到 Dev，模型仍偶发“本大爷”、普通宠物边界错误、人物编造和情绪承接不足。因此 SFT 是
v2 最可靠的基线，不是成熟的角色模型。

## 5. 主观 Judge GRPO 与前置 DPO

旧 Stage 3 GRPO 直接优化在线主观 Judge。技术训练和自动稳定性检查完成，但人工复核仅胜 2/10、
明显落后 4/10；生成稳定性、角色一致性、对话质量从 SFT 的 `8.0/5.2/5.7` 降到
`6.8/4.3/4.8`。该路线被封存，说明小规模在线主观奖励不能可靠保护整体质量。

前置 DPO 随后围绕数据和目标做了多轮受控实验：

| Run | 关键变化 | 人工结果 | 决策 |
|---|---|---|---|
| `20260809-2350` | 首轮 17 对，3 epochs | 胜 5/10，明显落后 2/10，三项均分均低于 SFT | 失败 |
| `20260811-0008` | 31 对，绝对质量门，RPO 0.3 | 胜 2/10，明显落后 1/10 | 失败 |
| `20260811-0024` | 仅将 RPO 提高到 1.0 | Dev 输出与上一 run 完全相同 | 失败 |
| `20260811-0114` | 17 条高质量最小编辑 pair | 胜 2/10，明显落后 3/10，4 条严重问题 | 失败 |

多轮训练中，正 preference margin 经常主要来自进一步压低 rejected，而 chosen 的绝对似然仍
下降。加入 RPO 能改善 chosen reward，却没有稳定转化为可见的 Dev 质量提升。数据绝对质量门
解决了部分稳定性退化，但 17～31 对的小规模偏好数据不足以稳定迁移角色能力，token 级训练也
容易学习偶然措辞而非可泛化的语义偏好。

v2 因此没有把任何前置 DPO adapter 交给后续 GRPO，后续规则型 GRPO 从冻结 SFT 重新开始。

## 6. 规则型 GRPO

v2 将 GRPO 目标缩窄为可自动验证的客观行为下限，不再在线优化角色自然度、情绪价值或复杂语义。
前两次规则型 run 未改善 Dev 规则分；Reward v2 校准后，`20260812-2144` 取得明确结果：

- 20/20 optimizer steps 正常完成，技术检查全部通过。
- 每个训练组 8 个候选均得到不同奖励，零方差组为 0，平均组内标准差为 `1.632`。
- Dev 规则均分从 SFT 的 `-3.123` 提升到 GRPO 的 `-0.949`，增量 `+2.174`。
- GRPO 按规则分胜 7/10。
- 硬无效与生成退化均从 SFT 的 2 条降为 0 条。
- 规则评分器统计的错误自称出现次数从 23 次降到 16 次，但受影响回答仍为 9/10。

该 run 证明连续、可排序的规则奖励能在小规模 GRPO 中提供有效学习信号。不过人工抽查仍发现
背景编造、关系与视角错位、意图和情绪承接不足、过度顺从以及局部语言混乱。run 状态保持
`awaiting_manual_review`，不能声称主观质量通过。

## 7. Post-GRPO DPO

post-GRPO DPO 只处理背景编造、视角错位和情绪承接三个明确问题。所有 run 都从
`20260812-2144` 的 GRPO adapter 开始，并使用 9 条隔离 holdout。GRPO 起点的 Reward v2 均分
为 `-1.7933`，错误自称共 15 次，退化和异常符号各 1 条。

| Run | 数据 / LR / RPO | Reward v2 均分 | 错误自称 | 退化 / 异常符号 | 结论 |
|---|---|---:|---:|---:|---|
| `20260813-0001` | 20 对 / `5e-7` / 0.3 | `-1.1506` | 16 | 1 / 1 | 7/9 输出不变，自动失败 |
| `20260813-0012` | 20 对 / `1e-6` / 0.3 | `-3.0412` | 18 | 3 / 2 | 更新过强，淘汰 |
| `20260813-0124` | 61 对 / `1e-6` / 0.3 | `-1.1202` | 11 | 3 / 3 | 自称改善但稳定性回退 |
| `20260813-0143` | 61 对 / `2e-7` / 0.3 | `-0.5764` | 12 | 2 / 2 | 综合最均衡，仍未通过 |
| `20260813-0201` | 61 对 / `3e-7` / 0.1 | `-1.8143` | 14 | 0 / 0 | 稳定但奖励与语义回退 |
| `20260813-0211` | 61 对 / `3e-7` / 0.3 | **`-0.3653`** | 16 | 2 / 2 | 奖励最高，角色稳定性回退 |

`0143` 使用修正后的 Teacher chosen，并以较低学习率取得最均衡结果：Reward v2 相对 GRPO
改善 `1.2169`，错误自称从 15 次降至 12 次；但退化和异常符号从各 1 条升至各 2 条，背景编造
3 条都没有明确解决。

`0211` 相对 `0143` 只将学习率从 `2e-7` 提高到 `3e-7`。其 Reward v2 再改善 `0.2112`，但错误
自称上升到 16 次，退化仍有 2 条；高均分还受到少数高分 holdout 的显著拉动。它说明 Reward v2
与部分目标改善相关，却不能覆盖角色称谓、事实可靠性、语言自然度和整体稳定性。

六个 post-GRPO DPO run 均为 `automatic_review_failed`。按预先约定的停止条件，v2 停止继续
扫描学习率、RPO、batch size 或 epoch；继续调参的预期价值低于重新建设数据与评测。

## 8. 关键经验

### 8.1 训练完成必须与训练有效分开验收

FP16 梯度溢出表明，仅检查退出码、loss 和 checkpoint 会放过无效训练。实际精度、有限梯度、
LoRA 参数变化和重载生成应继续作为所有版本的技术硬门槛。

### 8.2 自动奖励只能代表它测量的部分

Reward v2 成功解决了候选并列和规则排序问题，也能指导 GRPO 收紧客观下限；但 `0211` 的最高
均分与更多错误自称、病句和事实编造并存。规则分应继续作为过滤器和非回退门，不应作为整体
角色质量总分。

### 8.3 偏好数据质量必要但不充分

绝对质量门、最小分差、Teacher 修改比例和最小编辑合同减少了噪声，却没有让 17～61 对数据稳定
迁移复杂角色能力。v3 应优先提高语义覆盖、降低 chosen 的隐藏缺陷，并扩大独立评测，而不是继续
围绕相同小数据扫描训练超参数。

Teacher chosen 尤其不能只添加一句事实边界声明后继续编造；正确答案必须在未知处停止补写事实，
再自然邀请用户提供线索。`0124` 暴露并修正了这一数据审计盲区。

### 8.4 小 holdout 的均值很脆弱

post-GRPO DPO 只有 9 条 holdout，每类问题 3 条。单条高分即可明显抬高均值，同一个 seed 也会
使配置差异表现为少数离散输出变化。v3 至少应同时报告逐题结果、问题类型通过率和严重问题计数，
不能只按均值选模型。

### 8.5 单变量实验比组合调参更容易形成知识

`0201` 同时修改学习率和 RPO，只能淘汰组合而不能归因；`0211` 恢复 RPO 后才隔离出学习率影响。
小规模学习项目应限制每阶段实验预算，并坚持一次只验证一个明确假设。

## 9. v3 建议起点

1. 先明确 v3 的唯一主目标。若优先整体角色质量，从最终 SFT 开始；若优先验证规则型 RL 方法，
   可从 `20260812-2144` 开始，但必须先补人工复核。不要从任何失败 DPO adapter 续训。
2. 将 v2 的背景编造、视角错位、情绪承接和错误自称 bad case 转成新的训练分布，但重新生成
   Prompt，避免复用 Dev、holdout 或 Eval 文本。
3. 扩大语义 holdout，并在训练前冻结；每类问题应有足够样本支持按类型判断，保留逐条人工理由。
4. 在偏好训练前先确认 rejected 只含一个主要缺陷、chosen 没有隐藏事实或视角问题；数据不足时
   宁可减少目标维度，也不要用 Teacher 文本补齐数量。
5. 继续保留 Reward v2 作为硬过滤和回归门，但为主观目标建立独立人工 rubric，并用少量人工
   标签校准自动指标。
6. 在 v3 收尾前必须运行冻结 Eval，在相同后端、revision、模板、生成参数和 seed 下统一比较
   Base、SFT 及所有晋升候选。

## 10. 结论边界与保留范围

- 单角色、2B 模型、小数据、单主 seed 和单一评审者的结果不能外推。
- 不同阶段部分使用不同 Prompt 集，跨阶段 Reward 均分不能直接作统一排行榜。
- Stage 4 GRPO 的正式人工复核为空；post-GRPO DPO 的人工 review 因自动门失败而未启动。
- 冻结 Eval 未执行，因此 v2 没有完整的最终统一质量结论。
- 所有失败 adapter 只保留为实验和工程证据，不应作为 v3 默认初始化。

v2 的配置、阶段计划和奖励规约继续作为历史设计资料保留；运行过程、指标、失败原因和停止决策
由本文接替原 `RUNLOG.md` 与 `ISSUES.md`。原始运行产物暂保留在 `data/runs/morgana-v2/` 和
`output/morgana-v2/`，本次收尾不删除模型、日志、数据或 Git tag。
